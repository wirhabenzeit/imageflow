# Physical cover implementation plan

Draft for issue #154. [GitHub issue](https://github.com/wirhabenzeit/imageflow/issues/154)

The desktop draft implements template opt-in, saved cover artwork, a separate Cover editor, cover checks and PDF export, and MCP discovery, previews, edits, and synthetic checks. The Photobook starter offers the WhiteWall and Blurb formats. [Resolver](../../src/cover.ts) · [Desktop smoke](../../scripts/smoke-cover.mjs)

Templates can opt in to an exterior cover with its own geometry and PDF. A book using a cover-enabled format gets **Content** and **Cover** views in the same window. Each has its own canvas, layout picker, Inspector, and saved artwork. One book package supplies the photos, fonts, document settings, and Undo history to both views. [Cover sizing research](../../spikes/cover-sizing/README.md)

## Template opt-in

The template opts in by declaring a cover print specification for a format and at least one compatible `coverLayouts` entry. Gate the view switch, editor commands, and cover export on those declarations for the active format. A page or spread called `cover` is an ordinary content layout. The wall calendar opens directly in its usual editor, with its first sheet in the page sequence and a single **Export PDF** action. [Calendar template](../../sample/calendar/template/index.tsx)

A template can offer formats with and without exterior covers. Switching to a format without one returns to the content editor, hides the switch and cover export, and preserves saved cover artwork. Switching back makes that artwork available again. A cover-enabled format with an invalid draft page count still offers the Cover view.

## Editor and template boundaries

- Put the view switch in the book toolbar for cover-enabled formats. Content opens first. Returning to Content restores its selection, scroll position, and zoom. Use the existing apply and cancel behavior for pending edits when switching views.
- Cover shows one exterior sheet with optional trim, outer allowance, fold, and safe-area guides. The picker applies one layout to the entire sheet and saves the initial state when the user chooses one. Its Inspector edits cover artwork. Reuse photo placement and crop controls, parameter fields, and source browsing.
- Declare whole-sheet layouts in `coverLayouts` in the same template package. Each has one layout ID, one set of box and parameter declarations, and one render pass for the entire cover. Authors can share CSS and components with content layouts. Within Cover, layout switches keep matching fields and crops by ID and retain assignments from layouts that are no longer active.
- The cover render context exposes named regions in print order: back flap when present, back, spine, front, and front flap when present. Templates use those rectangles for panel-specific artwork and the sheet rectangle for artwork that crosses folds. Regions are placement and guide geometry. The picker and saved layout state operate on the whole sheet.
- Keep the existing interior title pages, printed inside covers, and the wall calendar's first sheet in the Content sequence. Give a starter photobook an explicit exterior cover as a sample of the new declaration. [Page templates](../decisions/0009-page-templates.md)

## Geometry and draft behavior

Start with a static cover specification associated with an existing interior format. The WhiteWall wrap provides the first end-to-end fixture. The Blurb dust jacket uses the same whole-sheet model and exercises both optional flap regions. Store printer dimensions and exact page-count bands as offline data. The resolver takes the interior page count from `pageSequence`, including blank interior pages, and returns the sheet, trim, panel, and guide rectangles in millimetres. Cover design state lives outside the interior sequence and text flow. [Draft cover sizing model](../../spikes/cover-sizing/data-model.md)

Recompute the sheet when the interior count or selected format changes. Panel-relative placement keeps the title aligned as the spine grows. If the count falls outside the supported range or step, keep the cover editable against the profile's minimum supported count, label that preview with both counts, and block cover PDF export until the geometry resolves for the actual count.

## Implementation order

1. **Resolve geometry against both printer fixtures.** Validate physical units, panel sizes, output limits, and exact coverage of permitted page counts. Exercise the WhiteWall spine threshold and the Blurb jacket thresholds below. Use one resolved geometry for guides, layout, checks, and output.
2. **Add saved cover state and template declarations.** Store the cover layout, parameters, boxes, and elements in optional `project.cover`. Read book formats 1, 2, and 3. Write format 3 when cover state exists and retain the lowest compatible format for other books. Gate cover templates with an additive contract capability so older apps report the unsupported feature. Before enabling cover saves, update all reference readers and writers, including asset usage, source removal, and template updates. Cover assignments kept by inactive layouts count as usage. Save and undo through the existing revision-checked project service. [Template capabilities](../decisions/0007-template-v1-baseline.md)
3. **Connect the cover editor and checks.** Use a cover-specific edit target for selection, mutations, and findings. Share the existing sandboxed renderer, assets, and editing controls where their contracts fit. Add cover locations to Book Check so findings can open Cover directly. Report an unresolved size or missing layout as a cover export blocker. Check spine text, safe areas, source availability, and photo resolution against the actual sheet. Test the calendar's single-view editor and PDF export, and verify that switching between formats with and without covers preserves the artwork.
4. **Export and verify both covers.** Offer **Export Content PDF** and **Export Cover PDF** for formats with a cover specification. Cover export produces one page through the existing Chromium/PDF preflight path. Use the full sheet for the MediaBox and BleedBox, inset the TrimBox by the outer allowances, and enforce the cover file-size limit. Use the existing export snapshot and revision checks. Stage separate actions first so an unfinished cover still allows content export. For both fixtures, verify cover editing, reopening, resize across a spine threshold, and PDF page counts and boxes. Test that a linked source used only by the cover is tracked and that removing it clears the assignment and can be undone.
5. **Complete the authoring surface.** Ship the cover capability, geometry, layouts, and findings in the SDK, docs, fixtures, and MCP contract with the editor. Verify MCP discovery, preview, draft edits, and commits for both printer fixtures, plus a calendar that rejects cover targets. Include a compatibility case for opening and saving an older book. [Desktop test workflow](testing.md)

## MCP interface

Extend the existing authoring tools. Use `cover: true` as an explicit address in requests that currently name a spread or page, with schema validation that requires exactly one address. A layout or spread ID called `cover` continues to resolve in its own namespace. Cover regions supply geometry. Agents address artwork within the sheet by its declared box or element ID. [Current MCP reference](../mcp.md)

- **Discover.** `get_authoring_context` exposes the runtime's cover capability, each format's cover specification, and the template's `coverLayouts`. `inspect_book` summary reports the active format's cover status. A dedicated `view: "cover"` returns the saved layout and assignments, actual interior page count, and resolved or provisional sheet and region geometry. The existing elements view can measure an explicit cover target.
- **Check and preview.** Pass `preview: { "target": { "cover": true } }` to `check_book` for the whole sheet, or add a box or element ID for a close-up. Image metadata identifies the cover, bounds, and any provisional sizing. Cover findings carry an explicit cover location. On an opted-in format, an invalid page count can return a labeled draft preview and a cover export blocker. A cover target on a format without cover support returns an availability error.
- **Edit.** Extend `apply_project_changes` with cover forms of the existing layout, parameter, source, and crop operations. A cover-targeted `switch_layout` selects or initializes the saved layout. Use `scope: "cover"` for layout parameters and `cover: true` for a box or element. The same operations work in `check_book` drafts. Mixed content and cover edits use one revision check and commit atomically. Results and checkpoint replays report `affectedCover` alongside affected interior spreads.
- **Verify the contract.** Advertise the new request forms and optional result fields through the tool schemas. Add a cover selection to synthetic layout fixtures with an explicit interior page count so authors can exercise spine and flap thresholds. Check that an ordinary calendar layout called `cover` still previews through its existing page or spread address. Keep PDF export and print preflight in the desktop export flow.

## Printer test cases

1. **WhiteWall Gallery Square, Fuji photo paper.** Use a front image and title, spine title, and back text. Expect **623 × 316 mm** at 32 interior pages and **624.5 × 316 mm** at 36. One added spread reaches 34 pages, which should show provisional dimensions and block cover export because this profile requires steps of four. [WhiteWall measurements](../../spikes/cover-sizing/README.md#whitewall)
2. **Blurb Large Square Hardcover, Dust Jacket, Premium Matte.** Put distinct artwork on both flaps and check that it stays attached to its region after resize. From 50 to 52 interior pages, the spine grows from 33 to 41 pt and each flap shrinks from 284 to 280 pt. The PDF stays **2377 × 882 pt**. Also check the exact point rounding at 102 pages, where the spine is 54 pt, each flap is 273 pt, and the PDF is **2376 × 882 pt**. [Blurb measurements](../../spikes/cover-sizing/README.md#blurb)

Validate both profiles with their respective PDF uploaders before relying on them for an order. Later iterations can add paper and binding selection, additional printer profiles, front-panel products, and combined PDF delivery. Paper and binding selection should resolve the effective interior format and cover specification together because those choices can change both page-count limits and cover dimensions.
